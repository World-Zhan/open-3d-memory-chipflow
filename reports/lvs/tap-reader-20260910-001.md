# PTAP1/NTAP1 reader 修复与严格 DCN 叶级 A/B

SPDX-License-Identifier: Apache-2.0

2026-09-10。**已修复限定的 X tap 读取问题；strict LVS 仍 FAIL。** [机器审计](tap-reader-ab-20260910-001.json)的 `audit_result=PASS` 仅表示本轮证据和 reader 行为通过审计，不能替代其中两个 `strict_lvs_result=FAIL`。

## 实际改变

独立复制的 IHP `custom_reader.lvs` 追加 `StrictTapXAdapter`。按照 KLayout 官方 `wants_subcircuit` API，仅截获大小写不敏感的 `PTAP1`、`NTAP1` X 元件，复用已有 R → `CustomTap`：按 TIE、WELL 顺序连接两端，A 从 m² 转 µm²，P 从 m 转 µm。未知子电路继续由原 reader 处理。

端子数错误、缺少面积/周长、零值/负值、非数值、未支持的参数或非单位 `.options scale` 都拒绝，不会静默创建零面积器件。当前不支持乘数 M；不更改 R 路径、源 PDK、版图、tap 提取、purge、align、simplify、严格端口或比较容差。

## 回归与实际 A/B

固定镜像 `sha256:92961478ad3c4f508efb42d9ccdba12ab262eb42a14926d2bd49862230ba8521`，KLayout 0.30.5。每个独立容器 2 CPU、4 GiB，内部 60 秒、外部 85 秒。四个 reader/leaf 容器均实际 exited 0、无 OOM；LVS 的工具正常退出仍伴随明确 `ERROR : Netlists don't match`。

- Reader：20 个用例、40 个语义断言，包括 12 个真实拒绝负例。SI/科学计数/大小写、W/L、PERIM、R tap、普通 10 kΩ 电阻与未知子电路层次均检查。见 `croc-lvs-tap-reader-regression-20260910-001`。
- 严格 DCN：只执行一个 control/candidate A/B。两臂各 31 个不可变观测快照；新 control 与前轮同阶段快照一致，两臂全部 layout 快照一致。见 `croc-lvs-tap-reader-dcn-ab-20260910-001`。
- 小型 LVSDB 只读 cross-reference：见 `croc-lvs-tap-reader-xref-20260910-001`。未运行 parent 或 full-chip LVS。

| 观测 | control | candidate |
|---|---|---|
| reader 后 PTAP1 | 空参数化子电路 | 真正的 CustomTap 器件 |
| align/simplify 后 PTAP1 | 被删除 | 保留 |
| 最终 schematic ANODE | 被删除 | 保留 |
| layout guard | RF purge 删除 | 同样删除 |
| schematic guard | simplify 删除 | 同样删除 |
| DCN circuit pair | NoMatch | NoMatch |
| Match 的 device pair | 0 | 0 |
| 未配对 device | 4 | 5 |

未配对数增加是恢复了原来丢失的 schematic tap；不代表 LVS 配对改善。即使 xref 显示 pin Match，也不能把 NoMatch 的电路提升为严格端口通过。

| tap 参数 | layout | schematic |

| A / µm² | 141.2964 | 141.253 |

上述值为真实快照观测，尚无合格的器件参数配对。叶级两个物理 cathode 分量仍与 schematic 的单个 cathode 不同；其真实父级金属闭合已有历史证据，本轮未做父级实验。
